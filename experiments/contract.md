# Experiment Data Contract

Standard contract for self-contained experiments. All experiments must follow **Required** constraints, should follow **Preferred** when possible, and may follow **Optional** constraints.

---

## Required

### Directory Structure
- `experiments/exp_{XXX}/` (XXX = zero-padded number)
- `experiments/exp_{XXX}/src/generate.py` (must exist)
- `experiments/exp_{XXX}/runs/{run_id}/` (created by `generate.py`)
- `experiments/exp_{XXX}/experiment.yaml` (must exist at experiment root)

### Function Signature
`generate.py` must define:
```python
def generate(run_id: str, max_queries: int | None = None) -> None:
```
Must handle both "dev" and "test" splits.

### Output Files
All outputs to `runs/{run_id}/`:

**`retrieval.jsonl`** (required fields):
```json
{"query_id": "string", "query": "string", "gold_video_id": "string", 
 "split": "dev"|"test", "retrieved_ids": ["video_id1", ...]}
```
- `retrieved_ids` = final results used for metrics and answer generation
- Optional: `methods` object for per-method details
- For multiple methods: `retrieved_ids` = final merged/selected results

**`responses.jsonl`** (required fields only):
```json
{"query_id": "string", "query": "string", "gold_video_id": "string",
 "context_video_ids": ["video_id1", ...], "answer": "string",
 "citations": [{"video_id": "string", "title": "string"}]}
```
- `context_video_ids` must match `retrieved_ids` from corresponding `retrieval.jsonl` entry
- No additional fields allowed (no `metadata`)

**`run_receipt.json`** (structure to preserve both splits):
```json
{
  "exp_id": "exp_001",
  "run_id": "r001",
  "query_set_id": "qset_v01",
  "dev": {
    "timestamp": "2025-12-27 17:57:45 UTC"
  },
  "test": {
    "timestamp": "2025-12-27 18:05:59 UTC"
  }
}
```
- Top-level required: `query_set_id`, `exp_id`, `run_id`
- Per-split objects (`dev`, `test`): Each must contain `timestamp`
- `timestamp`: Human-readable datetime format (e.g., "YYYY-MM-DD HH:MM:SS UTC"), used for registry sorting (system accesses `receipt["test"]["timestamp"]`)

**Important**: Since runs process both splits, the receipt must preserve data for both. Write once after both splits complete, or update per-split objects without overwriting.

**`extra.jsonl`** (optional): Experiment-specific metrics only, NOT standard metrics. Format: `{"split": "dev", ...metrics...}`

### Output Format Models
**MUST use:** `utils.models.AnswerResponse` and `utils.models.Citation` for `responses.jsonl`

### Split Handling
`generate()` must process both "dev" and "test" splits. Write outputs in append mode (files cleared at run start).

### Metrics Computation
- `generate.py` must NOT compute or write standard metrics (recall@k, MRR)
- `generate.py` must NOT create `metrics.json` (auto-generated by `utils/experiments.py`)
- `extra.jsonl` only for experiment-specific metrics, NOT alternative standard metrics

### Experiment Metadata File
**`experiment.yaml`** (strict format, cannot be altered):
```yaml
exp_id: exp_001
name: Experiment Name
description: |
  Multi-line description.
pipeline: |
  Step-by-step description.
```
Exactly these 4 fields, no more, no less.

### Integration Points
`generate.py` must add project root to `sys.path`:
```python
PROJECT_ROOT = Path(__file__).parent.parent.parent.parent
sys.path.insert(0, str(PROJECT_ROOT))
```

## Preferred

Can be bypassed if experiment requires different behavior. Document bypasses in experiment.yaml file in pipeline section under respective step.

### Data Access
- Use `utils.data.load_queries(path, split)` for loading queries from standard CSV format
- Use `data_ingestion.database.get_video_by_id(video_id)` for accessing shared video database

### Answer Generation
Use `utils.answer.generate_answer()`. Can bypass for different providers/formats. Must still produce `AnswerResponse` objects.

### Context Formatting
Use `utils.answer.format_context()`. Can bypass for chunking/custom formatting.

### Prompt Loading
Use `utils.data.load_prompt(prompts_dir, name)`. Can bypass for dynamic prompts.

### Directory Organization
Use `src/prompts/`, `src/utils/`, `src/data/` for experiment-specific code/data. Can bypass if simple.

### Git Tracking
Use `utils.git.get_git_info()`. Can bypass if no git.

---

## Optional

Best practices: Code organization, error handling, performance optimizations, documentation.

### Custom Data Ingestion
Experiments can create their own data ingestion pipelines, custom data sources, or alternative data access methods. Store experiment-specific data in `src/data/`.

---

Experiments must be self-contained for unique logic but must reuse shared data access and produce standard output formats.
